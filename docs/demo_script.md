# InsightPilot Agent 0.1.0 三项演示

操作路径更新于 2026-10-08，只使用内置或明确标注的合成数据。以下是可复现的演示步骤，不是已完成的真人试用记录。旧[工作台验收](workbench_redesign_acceptance.md)和手册截图仅代表各自记录日期，不作为本轮成绩；当前操作说明见[使用手册](user_manual.md)。

## 1. 指标诊断 → 城市当日探索 → 返回整体 → 报告

1. 在空闲的独立演示会话选择“内置模拟数据 → 交易转化异常分析”，规模“标准”、种子 42。等待数据就绪，输入“昨日订单量为什么下降？”，确认当前建议、指标与统计单位，点击“开始分析”。“昨日”指数据参考日 2026-06-30，不能解释为电脑昨天。
2. 先核对结果旁的源表、日期和方法，再按“发生了什么 → 变化集中在哪里 → 证据支持到哪一步 → 下一步”读结果。当前值、历史基准和变化以本次运行的真实表为准；不同维度贡献不能相加，静态份额不是跨期变化贡献。点击“查看证据与明细”可核对同一运行的证据与来源表。
3. 回“结论”，在城市表选择“西城”等确实存在的城市，核对筛选草稿，再点击“查看该城市当日表现”。子结果的路径应连到整体诊断，日期仍是父目标日；当日描述性汇总不能解释该城市跨期下降原因。
4. 直接点击结果旁“返回上一级分析”。父完整结果仍在时应直接展示原结果；已经释放时只显示父历史摘要。返回不触发重算，不将子结果换个标题当作父结果，也不需要绕到历史页。
5. 在父摘要点击“恢复该分析配置”。阅读将覆盖的草稿内容，先演示“保留当前草稿”，再重新进入并“确认恢复配置”。数据版本变化时须勾选“明确将该配置应用到当前数据并重新检查”；缺源表时先加载。恢复清除旧审批，本身不计算。
6. 预检通过后点击工作台主按钮“重新运行该分析”。检查新运行身份和来源，再在“报告”按需生成、下载 PDF。父摘要不能沿用子运行的 PDF；报告来自所选成功运行，未提交草稿不进入报告。

这一演示检查返回与恢复的区别，不预设业务下降百分比或节省时间。内存预算仍只保留一份完整结果，历史最多 10 条；不要为了演示恢复而增加缓存或刷新其他人使用的实例。

## 2. 24 行因果小样 → 原始差与调整估计 → 核对限制

使用现有[causal_fixture.csv](examples/user_manual/causal_fixture.csv)，按[手册第 8 节](user_manual.md#causal)上传和配置。它是合成教学数据，两组各 12 行。

1. 在“分析方法”找到“轻量因果探索”并点击配置。选择对应目标，处理字段为 group，结果与指标为 outcome；映射“协变量”和参数“控制变量”均选 covariate。处理值选 treatment，对照值选 control，确认映射并应用参数，再明确开始。
2. 未筛选的完整小样中，对照均值 15.5、处理均值 17.5；原始差为 2，OLS 调整估计为 2，有效样本 n=24。核对实际 adjusted_effect_summary 与报告。原始差和调整估计并列，不相加；本方法没有倾向评分加权结果或未计算的区间。
3. 说明估计沿用 outcome 的原单位，字段齐全、流程完成与两组各 12 行都不能证明随机化、独立性、无未观测混杂或因果识别。去掉控制变量后只能展示原始差与未执行调整的限制，不能补出调整值。

此案例保留专业路径的可发现性与解释深度。数字来源及小样边界见[教学数据说明](examples/user_manual/README.md)，不将教学构造效果写成真实业务收益。

## 3. 两个转化率候选 → 必要澄清 → 阻断或明确执行

使用既有 `tests/test_upstream_definitions_clarification.py` 中 `rates()` 的四行合成小样。为浏览器练习，可将以下同值内容保存为本地 `daily.csv` 后上传；不是业务数据：

```csv
date,orders,visitors,payment_attempts,successful_payments,cvr,payment_success_rate
2026-01-01,1,2,2,1,0.5,0.5
2026-01-01,9,90,10,9,0.1,0.9
2026-01-02,3,10,5,3,0.3,0.6
2026-01-02,2,10,5,2,0.2,0.4
```

1. 在新会话中输入“转化率为何下降？”。暂不替使用者选择指标，查看 cvr 与 payment_success_rate 的实际候选；未确认时应停在待补充状态，没有成功统计结果，画像也不能冒充回答下降问题。
2. 明确选择 cvr，即 orders/visitors，点击“确认口径选择”，核对日期和当前方法再提交。已有小样口径对应两日加权比率 10/92 与 5/20；不能平均逐行百分比，也不能因为问题写了“下降”就声称结果一定下降。只有两个日期不足以支持稳定的历史异常判断，应读取实际限制。
3. 另用案例 2 的配置把“结果字段”明确清为“不选择”，检查缺口与阻断；重新选择真实 outcome、确认映射并应用参数后，才允许明确执行。不要把组值 treatment 当字段名，也不以无关数据概览替代因果问题。

真人观察使用[三任务观察表](core_workflow_observation.md)，由使用者实际操作后填写；脚本、AppTest、截图与健康检查分别记录，不替代真人完成情况。维护者可在隔离工作副本使用 `scripts/check_core_workflow_browser.py` 串联检查主闭环；只有最终脚本完整退出 0 才能记录自动浏览器全链路通过。性能前后测使用 `scripts/benchmark_core_workflow.py`，纯返回与重新运行分开记录，均不构成真人试用结果。
