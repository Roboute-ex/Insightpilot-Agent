# 分析建议与错误恢复

适用版本：0.1.0。界面与建议规则核对日期：2026-09-29。

## 从问题开始

1. 选择数据来源并等候数据摘要显示已就绪。内置场景、CSV/Excel 和已支持的只读数据库继续可用。
2. 输入问题，按 Enter 或移开焦点。系统使用已准备的字段、真实取值和口径摘要更新建议；此时不会运行分析。
3. 查看“建议”“实际将采用”和当前状态。存在会改变答案的口径歧义时，明确选择后点击“确认口径选择”。
4. 配置可用后点击“开始分析”。不要把查看建议、应用参数或接受推荐当作已经执行。

默认三个常用示例先经过当前数据适配检查。“更多示例”保留完整示例目录；点击“使用此示例”会原子填入问题、清理旧方法专属参数并恢复自动推荐。提示为“已填入示例并恢复自动推荐”。内置场景已声明的口径可以复用，但示例不会替用户确认自定义数据的净/毛收入、多个转化率或实验方向。

## 自动、手动和旧配置

新会话默认“自动推荐分析方法”，不是注册表第一项。自动建议考虑问题、分析范围、字段映射、指标口径、参数和数据摘要。原自动工作流仍是合法目标：订单下降问题优先做描述性指标诊断、漏斗拆解和维度变化，不因为含有“为什么”就做因果推断。

在“调整方法与参数”中可以明确选择方法。来源记录为 `user_selected`，主摘要会继续显示，即使调整面板已收起。只编辑问题不会悄悄覆盖手动选择；问题与方法冲突时需要接受推荐，或明确修改目标和配置，再通过检查。

升级前会话若保留某个方法，但无法判断是否由用户主动选择，显示“旧会话保留的方法（来源尚未确认）”。可以点击“改用推荐方法”，或“明确保留当前方法”。后者只确认选择来源，仍不能绕过字段和安全要求。恢复历史则使用该节点配置并标记“从历史恢复”，重新检查数据身份和本次请求，不沿用过期审批。

## 从全部方法进入因果分析

首页展开“查看全部分析方法”，不需要先打开高级设置。目录完整保留十个剧本，每个条目均能查看用途、要求、当前缺口并点击“配置：方法名”。不可用方法仍可配置，执行按钮继续受同一预检约束。

1. 点击“配置：轻量因果探索”，现有“调整方法与参数”和字段映射会打开；当前分析表和指标保持不变，问题与分析目标不会被代改。
2. 若原目标是订单诊断，明确把“分析目标”改为“轻量因果探索”，并输入相应问题。仅更换方法不表示用户同意更换目标。
3. 配置真实的处理字段、结果字段及需要的协变量，核对指标和聚合方式，点击“确认当前字段映射”。`treatment/control` 是数据中的两个组值，不是字段名。
4. 在方法参数中明确选择处理组值、对照组值和控制变量，点击“应用参数并更新建议”。预检仍不通过时按缺口修正，不会运行统计或建立成功历史。
5. 配置就绪后点击“开始分析”。结论展示真实均值差、可用的回归调整估计及样本量；明细选择 `adjusted_effect_summary`；报告中按需生成 PDF 或其他五种格式。

只有一组、真实组值不匹配、缺少处理/结果字段或结果全空会阻断。原交易数据没有可用处理字段时，需改用推荐诊断或另外提供满足条件的数据，系统不会制造处理组。估计沿用结果变量原量纲；即使运行成功也不是因果证明，随机化、无未观测混杂、重叠性与时序前提仍需核实。无有效控制变量时只展示未经调整差异，当前剧本不执行倾向评分加权。

## 修复截图中的因果选择

对于交易数据上的“昨日订单量为什么下降”，手动选“轻量因果探索”但没有有效 `treatment_column` 时，页面会直接说明缺少处理/对照分组字段。`treatment`、`control` 是组别取值，不能代替字段。已明确结果列时，不应再泛称缺少结果变量。

- 点击“改用推荐方法”：仅更新为自动建议并重新预检。推荐替代方法通过当前数据检查后，此按钮才可用。随后由用户另行点击“开始分析”。
- 点击“补充字段配置”：打开“配置分析范围与字段映射”，选择真实目标表与字段。数据中确实缺少必要字段时，需要提供合适数据；系统不会随机制造处理组。
- 坚持其他研究目标：在高级设置中明确修改分析目标，同时提供该目标所需数据。不能靠选择一个方法绕过预检。

因果探索会检查实际处理字段、结果字段、有效组值和数值样本。实验还要求独立统计单位与比较方向。数字 `0`、`1` 可以在明确映射及组值选择后使用；字段名称不必叫 group，但系统不会把任意二分类字段自动视为实验分配。没有协变量时只披露未调整的两组差，不能伪称已控制混杂。字段齐全也不能证明随机化、独立性、无未观测混杂或因果识别成立。

## 输入状态、审批和运行状态

|预检状态|含义与动作|
|---|---|
|`ready`|配置允许进入执行门禁。点击开始后仍核对安全、数据与统计契约，不代表结论已验证。|
|`needs_clarification`|待补充信息，例如缺分组字段、对照方向或有多个指标口径。完成相应明确操作后再开始。|
|`invalid_input`|输入配置无效，按就地原因修正字段或参数。|
|`unsupported`|现有引擎不能回答该目标，或当前条件不支持。应明确换问题/目标，不能用无关结果冒充回答。|

预检未通过时不提交后台分析任务、不执行分析SQL或统计，也不创建成功历史。审批属于另一道门禁：待审批计划需要复核指定计划，不能由推荐或旧审批自动通过。真正运行后的 queued/running/completed/failed/cancelled 等任务状态与上述输入状态分开；引擎异常仍显示“分析执行失败”和脱敏原因。

存在上次成功结果时，未通过的新请求不会冒充已有结果。页面明确标注“上次成功结果”；其报告使用已执行配置，不使用编辑中或尚未应用的参数。缺少确定性输入不会通过重复点击自动修复，应先完成提示的恢复动作。

## 范围、参数和结果

“查看数据”里的预览表只控制预览；更换预览表不改变分析答案。真正的目标表在“调整方法与参数 → 配置分析范围与字段映射 → 分析范围：目标数据表”选择。字段控件的建议值不等于确认，有歧义时仍需明确操作。

方法参数位于独立表单。编辑后先点击“应用参数并更新建议”，等待重新预检，再点击主“开始分析”。没有提交表单的参数尚未到达后端，不能用旧建议执行这些新值。方法、数据修订、映射或有效参数变化会使请求身份变化，并清理失效确认/审批；旧后台结果不能覆盖新请求。

结果通过“结论、图表、明细、报告”查看。明细保留分页，图表按选项构建。“报告”中依次为 PDF、Markdown、HTML、Excel、运行清单JSON、ZIP；点击对应生成按钮才生成。选择ZIP会按报告包需要生成其中格式，不等于每次分析都预生成六类文件。仅成功完成的所选运行能生成成功分析报告；历史完整结果已释放时应恢复配置并重新执行。

## 接口与边界

UI、CLI、workflow 共用 Planner 中的 `prepare_analysis_request` 与建议对象 `analysis_advice`。它区分 requested/recommended/effective 方法，并提供稳定原因码、中文原因、相关字段和修复动作。方法是否与问题相关，与数据能否支持执行，分别判断。建议使用准备阶段的精确摘要，不重新扫描整份源数据。

CLI 的 `--advise-only` 成功取得建议时退出0，即使 `can_submit=false`；其 `execution_status=NOT_STARTED`，不表示分析成功。实际执行被输入门禁阻断退出2，待审批退出3，引擎失败退出1，导出失败退出4。`--plan-only` 保留预览语义，不执行分析SQL，也不能绕过澄清或审批。JSON保留英文稳定键，新增建议和预检字段。为兼容旧API，未提供选择来源、`playbook_id=None` 且显式给出目标的历史调用仍可保留原自动工作流；新UI明确传入自动选择语义。

这是有限中文规则推荐，不是通用自然语言理解或置信概率。已覆盖常用同义、部分否定和明确边界；复杂修饰仍可能需要用户调整。未来预测、因果证明等未实现目标不能用历史趋势替代。全部方法仍受原SQL、Join、只读连接、审批和缓存预算约束；DuckDB/SQLite之外未认证方言继续拒绝。不接在线模型，不要求API key。
